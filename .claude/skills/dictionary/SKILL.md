# nobetsu の辞書を育てる

利用者は音声入力で喋っています。文章の中の誤変換は、**書いた本人には直せません**。
喋った本人には正しく聞こえているからです。前後の文脈を読める側が拾うしかありません。

## このスキルの性質

一度発動したら、**このセッションの以後すべての発言**に対して働き続けます。
毎回呼び直す必要はありません。

「もういいよ」「終わり」「辞書は止めて」と言われたら止めます。

---

# 段階（レベル）

**丁寧にやるほど当たるようになり、同じだけ危なくなります。**

登録を1本に絞れば安全ですが、同じ言い回しでしか当たりません。
崩れ方を先回りして束ねれば当たるようになりますが、正しく喋った文章を壊しはじめます。
過去の登録を疑って本人に確かめれば精度は上がりますが、**問いかけそのものが仕事の邪魔**になります。

どこまで踏み込んでよいかは人と場面で変わるので、**設定にしました。**

| | 名前 | 足されること | 代償 |
|---|---|---|---|
| **1** | そのまま | 目の前で起きた誤変換を1本だけ登録する | 同じ言い回しでしか当たらない |
| **2** | 類推 | 同じ言葉の**他の崩れ方**も用意する | 観測していない規則が正しい文章を壊す |
| **3** | 整理 | 辞書**全体**を見て、衝突と死に規則を直す | 直した規則が別の場所で効かなくなる |
| **4** | 追跡 | 会話の中で登録済みを疑い、必要なら**本人に聞く** | 問いかけが雑音になる |

**上の段階は下を含みます。** レベル3はレベル1と2をやったうえで整理します。

## いまのレベルを知る

```bash
head -1 .local/dictionary-level
```

- 数字（1〜4）が返る → それがこの Mac のレベル
- ファイルが無い → **レベル1** として扱う。**勝手に作らないこと**

`.local/` はこの Mac だけの置き場で、git では追跡していません。
クローンしただけの人はレベル1（いちばん保守的なもの）から始まります。

## 名乗る

**セッションで最初にこのスキルが動いた回だけ**、返答の最後に1行足します。

```
辞書: レベル4（追跡）で動きます。このままでよろしいですか。変えるときは「辞書レベル2」と言ってください。
```

**返事は待ちません。** そのまま仕事を続けます。
黙って動くと、なぜ勝手に登録されたのか・なぜ聞かれたのかが分からなくなります。
かといって返事を待つと、毎セッションの冒頭が問答から始まって鬱陶しくなります。
**名乗るが、止まらない。**

## レベルを変える

「辞書レベル2」「レベルを下げて」「もう聞かないで」「もっと積極的に登録して」など、
言い方は決めません。**意図が読めたら変えます。**

```bash
printf '3\n# 2026-08-25 聞かれるのが煩わしいと言われたので下げた\n' > .local/dictionary-level
```

1行目が数字。2行目以降は自由（`#` で理由と日付を残す）。
変えたら1行で報告します。**次のセッションからではなく、その場から新しいレベルで動きます。**

# レベル1 — そのまま

## 毎回やること

1. **まず頼まれた仕事に答える。** 辞書はそのついでで、主役ではない
2. 文章の中の誤変換を拾う
3. 変更前に管理ツールで既存規則を探し、基準を満たすものだけ `dictionary.txt` へ反映する
4. 満たさないものは候補行として残す。同じものが2回出たら昇格させる
5. 報告は1行だけ

## 登録してよいもの（3つすべてを満たすこと）

- 前後の文脈から、**元の言葉が一意に決まる**
- 言い間違いではなく、**聞き間違い**である
- 左（認識結果）が、この人の普段の文章に**別の意味で現れない**

## 登録してはいけないもの

- 短くありふれた語を単独で（「苦労」「黒」「今」「1階」など）
- 言い直し・言い淀み・助詞の崩れ。**それは認識器のせいではない**
- 文脈がないと決まらないもの（「EM」は LLM かもしれないし Engineering Manager かもしれない）
- 一度きりの崩れ方。二度と同じ形にならないものを登録しても当たらない

**迷ったら登録しない。候補に落とす。**
誤登録は、正しく喋った文章を壊します。何も登録しないより悪い側の失敗です。

## 左をどこまで伸ばすか

**一意に決まる最短の長さ。** 助詞まで含めてよい。

| 危ない | 安全 |
|---|---|
| `苦労 => Clone` | `苦労してくる => Cloneしてくる` |
| `黒 => Claude` | `黒で開発 => Claudeで開発` |

長い規則から先に当たるので、短い規則と併記しても長い方が勝ちます。

## 書いてはいけない形

**左が右の一部になっている規則は書けません。**

```
品予約履歴 => 備品予約履歴     ← だめ
```

正しく「備品予約履歴」と認識されたときにも中の「品予約履歴」が引っかかり、
「備備品予約履歴」になります。直せば直すほど壊れる規則です。
アプリ側でも読み込み時に捨てますが、そもそも書かないこと。

前に一文字足して、右に含まれない形にすれば書けます。

```
枠スペース => ワークスペース   ← よい
```

## 候補の残しかた

`#` で始まる行はアプリから無視されるので、辞書ファイルの末尾にそのまま残します。

```
#? EDM => LLM （EDM は音楽の意味がある。2026-08-22）
```

同じ誤変換が**2回目**に出たら、候補行を消して本登録します。
一度きりの崩れではないと分かった時点が、登録してよい瞬間です。

## 追加・修正・削除は1つの入口から行う

手作業の `grep` と行編集では、表記が少し違う過去の登録を見落とします。
編集はすべて次の管理ツールを使います。

```bash
.claude/skills/dictionary/manage.sh find '探したい語'
.claude/skills/dictionary/manage.sh set '認識結果' '正しい文字'
.claude/skills/dictionary/manage.sh replace '古い左辺' '新しい左辺' '新しい右辺'
.claude/skills/dictionary/manage.sh delete '消す左辺'
```

- `find` はまず問い合わせ全体を固定文字列で探す。無ければ少しずつ切り詰めた部分候補を長い順に出す
- `set` は **upsert**。左辺があれば右辺を更新し、無ければ追加する。`#?` の同じ左辺があれば本登録へ移す
- `replace` は左辺そのものを取り違えていたときに、左右を一度に直す
- `delete` は本人が削除を明示したときに使う。通常の弱い規則は削除せず `#?` へ落とす

**曖昧検索の候補をそのまま変更してはいけません。** `replace` と `delete` は、候補表示で
確認できた古い左辺を完全一致で渡します。候補が複数残るなら、会話とログで絞るか本人に聞きます。
管理ツールは書く前にアプリと同じ `PhraseBook` で辞書全体を検証し、衝突があれば変更しません。

# レベル2 — 類推（同じ言葉の他の崩れ方も用意する）

**同じ言葉が、毎回同じ形に崩れるとは限りません。**
「curl」は「カール」とも「変わる」とも書かれます。
レベル1は目の前で起きた1本しか登録しないので、次に別の形で崩れたらまた素通りします。

だから登録するとき、**右辺（打ちたい文字）を固定したまま、左辺の別の形を1〜3個思い浮かべます。**
思い浮かべるところまでは無条件にやってよい。
**登録するかどうかは、1本ずつレベル1の基準にかけて決めます。**

```
カールコマンド => curlコマンド     ← 登録。カタカナの「カール」に「コマンド」は続かない
変わるコマンド => curlコマンド     ← 候補どまり。「仕様が変わるコマンド」を壊す
```

ここを間違えると、この人が本当に「仕様が変わるコマンド」と言いたいときに、
**毎回 curl に化けます。** しかも本人からは原因が見えません（自分で書いた辞書ではないので）。

**変種は、観測していない誤変換です。**
目の前で起きた1本より根拠が弱いので、迷ったときの落とし先は候補（`#?`）です。
レベル2は「登録を増やす」段階ではなく、**「候補を増やす」段階**だと思ってください。

## 変種には出どころを書く

あとで疑うときの手がかりになります（レベル4）。

```
カールで叩く => curlで叩く  # 類推 2026-08-25（観測したのは「カールコマンド」）
```

観測した本体には何も書きません。**印が付いている＝弱い根拠**、という読み方にします。

# レベル3 — 整理（辞書全体を見て最適化する）

規則が増えると、**規則どうしがぶつかりはじめます。**
1本ずつは正しいのに、束にすると壊れる、という壊れ方をします。
辞書は上から順に全部当てるので、**先に直した結果を、後ろの規則がもう一度直しにいきます。**

**これは目で見ても見つかりません。道具で判定します。**

```bash
.claude/skills/dictionary/check.sh
```

やっていることは1つだけです。
**辞書のすべての右辺（＝すでに正しい文字）に、辞書全体を当て直します。**
そこで何かが書き換わったなら、その辞書は**正しい文章を壊します**。

アプリと同じ `PhraseBook`（`Sources/Phrases.swift`）を呼ぶので、判定は本番と同じです。
初回だけコンパイルに数秒かかります。

管理ツールも書く前に同じ検証をしますが、短すぎる左辺などの警告も見るため、
**登録・修正・削除をしたら毎回走らせ、指摘が出たら直してから終わります。**

過去の文章に当てて確かめることもできます。長い文章を1本渡せば、
壊れる箇所だけが差分で出ます。

```bash
.claude/skills/dictionary/check.sh --on ~/Desktop/きのうのメモ.txt
```

## 道具では出ないので、目で見るもの

登録のついでに、辞書全体を一度ながめます。

- 短すぎて危ない規則があれば伸ばす
- 同じ結果になる重複を消す
- 使われた形跡のない一度きりの規則は候補へ落とす
- `# 類推` の付いた規則が溜まっていたら、当たっていないものから捨てる

本人が削除を明示していないときは、削除ではなく候補（`#?`）へ落とし、理由と日付を書きます。
理由が残っていないと、半年後に同じ規則をもう一度登録して、同じ事故を起こします。

## 修正・削除も次のひと言から効く

個人辞書はアプリへ焼き込まないため、追加だけでなく**修正・削除もビルド不要**です。
アプリは喋りはじめる瞬間に読み直します。

# レベル4 — 追跡（会話の中で見直す。必要なら本人に聞く）

ここから先は、**過去の自分の登録を疑う**段階です。

## 1. 本人のメタ指示を最優先で拾う

会話の途中で「いまのこれは○○のことね」「そこは△△って言いたかった」と言われたら、
**それが正解です。** 推測をやめて、そのとおりに登録・修正します。

このとき、**その発言自体の誤変換も一緒に直します。**
訂正しようとした文章がまた誤変換されている、というのは普通に起きます。

## 2. 辞書が壊した跡を探す

目の前の文章に、**辞書の右辺が場違いな位置で現れていないか**を見ます。
出ていたら、それを作った規則を疑います。

```
「そこの仕様がcurlコマンドなんだよね」  ← 「変わるコマンド」を壊している
```

疑わしい規則は、**削除ではなく絞り込み**を先に考えます（左を伸ばす）。
絞り込めないなら候補へ落とします。`# 類推` の付いた規則は真っ先に落として構いません。

## 3. 元が絞り込めないときだけ、本人に聞く

- **1回の返答につき最大1件。** まとめて聞かない
- 候補（`#?`）に落として済むなら**聞かない**。次に同じ形が出たときに聞けばよい
- 聞き方は、該当箇所を引用して、**こちらの推測を2つまで並べる**

```
辞書: 「再広報のレベル」は「最高峰のレベル」でしょうか、「再構成のレベル」でしょうか。
```

「本当は何と言いたかったですか」とだけ投げないこと。
喋った本人には**正しく聞こえている**ので、何を聞かれているのか分かりません。

## 4. 手打ちと聞き間違いを混同しない

キーボードで打った文章に誤変換はありません。あるのは打ち間違いで、
**それは辞書の仕事ではありません。**
打ち間違いを辞書に登録すると、正しく喋った文章が壊れます。

nobetsu のログを見れば、その発言が喋られたものかどうかが分かります。

```bash
date "+%H:%M:%S"; tail -80 ~/Library/Logs/nobetsu.log | grep -E "長押し|入力先を見張る|待機中"
```

```
[13:44:42.766] ⌘ 長押しを検知 → 開始
[13:44:42.770] focus: 入力先を見張る（Claude）
[13:50:37.158] engine: running=false 待機中
```

- 発言が届いた時刻が、**開始から待機中までの間**に入っている
- `入力先を見張る（…）` が、**いま話しているアプリ**である

この2つが揃えば、喋った文章です。ログの時刻はこの Mac の時刻なので、`date` と並べて見ます。

**ログが無い／アプリが動いていない環境では、音声入力だと決めつけません。**
その場合はレベル3までの動きに落とし、登録ではなく候補にとどめます。

# 書き込み先

`dictionary.txt`（リポジトリ直下）**1枚だけ**を触ります。
このファイルは `.gitignore` されています（公開リポジトリに個人の語彙を出さないため）。
見本の `dictionary.sample.txt` は触りません。

`~/Library/Application Support/nobetsu/dictionary.txt` はこのファイルへの
シンボリックリンクなので、**書いた瞬間から効きます。ビルドは要りません**
（アプリは喋りはじめる瞬間に読み直します）。

リンクが無い Mac（会社の Mac など）では、最初に一度だけ作ります。

```bash
ln -s "$(pwd)/dictionary.txt" ~/Library/Application\ Support/nobetsu/dictionary.txt
```

# 報告のしかた

作業の邪魔をしないこと。返答の最後に1行。

```
辞書: 「クロノMD」→ CLAUDE.md を登録。候補に2件。
```

レベル2以上で変種を足したときは、そう分かるように書きます。

```
辞書: 「カールコマンド」→ curl を登録。類推1件・候補2件。
```

修正・削除も、何をどうしたかだけを1行で報告します。

```
辞書: 「Appサート」の右辺を upsert に修正。
辞書: 誤登録「変わるコマンド」→ curlコマンド を削除。
```

登録も候補も無い回は、**何も言わない**。毎回報告すると、それ自体が雑音になります。
（名乗りの1行だけは、セッションの最初に必ず出します）

# 効いているかの確認

```bash
tail -20 ~/Library/Logs/nobetsu.log | grep phrases
```

`phrases: 辞書を読み込んだ N 件` の N が増えていれば読めています。
