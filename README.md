# nobetsu（のべつ）

**日本語話者のための、のべつ幕なしに喋り続けられる音声入力。**

macOS 26 以降の `SpeechAnalyzer` / `DictationTranscriber` を使い、
話した端から画面に文字が出て、時間制限がなく、日本語入力（IME）を経由しない。
すべて端末内で完結し、音声も文字も外部に送信しない。

> **のべつ幕なし** — 芝居で幕を下ろさずに演じ続けること。転じて、絶え間なく続くこと。

---

## なぜ作るのか

AI エージェントに長文を話しかける用途で既存の音声入力を使うと、日本語話者は必ずどれかに当たる。

| ツール | 詰まるところ |
|---|---|
| macOS 標準の音声入力 | ライブ変換と衝突して、変換のたびに固まる・止まる |
| Claude Code / Gemini のマイク | 数分で切れる。長文を一息で入れられない |
| ChatGPT | 長文は入るが、**喋っている間に文字が一切見えない** |
| 既存の OSS 音声入力 | ほぼ全部が「押す→喋る→離す→一括ペースト」型。つまり上と同じ |

そして最後の欄が重要で、既存の OSS はほぼすべて英語圏の開発者によるものだ。
**英語には変換工程が存在しないので、ライブ変換と音声入力がぶつかるという問題自体が起きない。**
だから誰もそこを解こうとしない。ここが構造的に空いている。

nobetsu はそこだけを狙う。

## 設計方針

1. **IME を経由しない** — `DictationTranscriber` は漢字かな交じりの確定テキストを返すので、
   ライブ変換に渡さず直接アプリへ挿入する。変換の衝突が原理的に起きない
2. **喋りながら見える** — 途中経過（volatile）を薄い色で、確定テキストを濃い色で表示する。
   多少遅れてよい。見えないことのほうが困る
3. **時間制限を設けない** — 何分でも喋り続けられる
4. **自分の語彙に育つ** — `SFSpeechLanguageModel` によるカスタム言語モデルで、
   自分がよく使う固有名詞や言い回しに馴染ませる
5. **端末内で完結** — API キー不要、アカウント不要、通信なし

## 動作要件

- macOS 26 (Tahoe) 以降
- Apple Silicon（Neural Engine を使用）

## 使う

```bash
./build.sh
open build/nobetsu.app
```

メニューバーに波形アイコンが出る。Dock には出ない。

| 操作 | 動き |
|---|---|
| **⌘ を長押し** | 認識が始まる。指を離しても続く |
| **もう一度 ⌘ を軽く叩く** | 停止 |
| **ESC** | 停止 |

話した内容は**そのとき使っているアプリにそのまま入っていく**。
画面下部に認識中の文字が浮かぶので、挿入先が見えなくても確認できる。

⌘ は macOS のあらゆるショートカットの起点なので、
**⌘ を押している間に他のキーやクリックが来たら、それはショートカットだと見なして発火しない**。
⌘Tab や ⌘S を打とうとしてためらっても暴発しない。
それでも気になる場合は、メニューから「右の ⌘ だけで開始する」に切り替えられる。

### 必要な権限

| 権限 | 何に使うか |
|---|---|
| マイク | 音声の取り込み |
| 音声認識 | 端末内での文字変換 |
| **アクセシビリティ** | **⌘ の長押しを見張り、文字を他のアプリへ打ち込むため。これが無いと何も動かない** |

### 開発中の注意

アクセシビリティ権限は**コード署名の同一性に紐づく**ため、アドホック署名のままだと
ビルドのたびに許可し直しになる。キーチェーンアクセスで `nobetsu-dev` という名前の
コード署名用の自己署名証明書を作っておくと、`build.sh` が自動でそれを使い、許可が維持される。

## 仕組み

```
マイク
  ↓  AVAudioEngine
SpeechAnalyzer + DictationTranscriber (ja-JP, 端末内)
  ↓  未確定テキスト / 確定テキスト
TextInjector
  ↓  CGEvent の Unicode 直接入力（IME を経由しない）
そのとき使っているアプリ
```

未確定テキストは**確定を待たずに先に打ち込む**。認識が書き換わったら、
前回打ち込んだ文字列との共通接頭辞を求めて、**食い違った末尾だけを消して打ち直す**。
確定を待つ設計にすると、下の計測どおり 20 秒以上も文字が出てこない。

## spike の計測結果 (2026-08-21)

`spike/` に、3つのエンジン構成を実測して比較するアプリを残してある。
MacBook Air M4 / macOS 26.5.2 / 日本語の自然な発話 80〜105 秒での結果。

| | Dictation +<br>frequentFinalization | Dictation | SpeechTranscriber |
|---|---|---|---|
| 初回表示まで | 1.63 秒 | 1.33 秒 | **11.79 秒** |
| 途中経過の遅延 平均/最大 | 0.16 / 0.38 秒 | 0.16 / 0.38 秒 | 0.08 / 0.18 秒 |
| 確定の遅延 平均/最大 | 0.42 / 0.86 秒 | 0.32 / 0.52 秒 | **3.78 / 8.34 秒** |
| 誤り | 500字中 7 箇所 | 668字中 5 箇所 | 531字中 5 箇所 |

**SpeechTranscriber は喋りながら見る用途には使えない。** 初回表示に 11.79 秒かかり、
確定は最大 8.34 秒遅れる。実際に「文字が出ないと思ったらいきなり出てきた」という挙動になる。
精度自体は3構成とも大差なく、誤り率はおよそ 1.2〜1.5%。
